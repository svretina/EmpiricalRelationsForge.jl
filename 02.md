# Milestone 01 — Initialize EmpiricalRelationsForge.jl

EmpiricalRelationsForge.jl will be a separate Julia package for discovering, fitting, validating, and comparing new empirical relations from numerical data.

It should complement your existing `EmpiricalRelations.jl` library rather than duplicate its functionality.

The distinction between the libraries is:

| Package                    | Responsibility                                                                                                             |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| EmpiricalRelations.jl      | Community reference database, published empirical relations, citations, waveform measurements                              |
| EmpiricalRelationsForge.jl | Regression, symbolic discovery, model selection, validation, uncertainty analysis, and creation of new empirical relations |

The first package provides the scientific evidence and existing models. The second provides the tools for discovering and evaluating new models.

## 1. Proposed architecture

EmpiricalRelations.jl

Raw waveform database • EOS properties • published relations

Data preparation

Select frequencies • choose features • validate data • normalize units • prevent duplicates

Classical regression

Linear • polynomial • nonlinear • weighted least squares

Symbolic regression

SymbolicRegression.jl • custom operators • expression constraints

Model evaluation and selection

Residuals • cross-validation • EOS generalization • complexity • uncertainty

Candidate empirical relations

Formulas • coefficients • plots • training provenance • reproducible results

I would design the package with two independent modeling backends sharing the same data preparation and validation infrastructure.

### Classical regression

Start with ordinary least squares, polynomial basis regression, and weighted least squares. These provide useful baselines and reproduce the general types of fits commonly used in the BNS postmerger literature.

### Symbolic regression

Use [SymbolicRegression.jl](https://github.com/MilesCranmer/SymbolicRegression.jl?utm_source=chatgpt.com) to discover mathematical expressions without fixing a particular functional form beforehand.

The current package supports both a high-level `SRRegressor` interface that accepts Tables.jl-compatible inputs and a low-level `equation_search` interface. Its Pareto frontier allows you to compare expressions based on fit quality and mathematical complexity.&#x20;

## 2. Proposed user-facing API

The eventual workflow should look approximately like this:

```
using EmpiricalRelationsForge

# Obtain and prepare published numerical measurements
dataset = load_dataset(
    :f_peak;
    features = [:M_chirp, :Lambda_tilde],
    source = :EmpiricalRelations
)

# Fit a conventional polynomial model
baseline = fit(
    dataset,
    PolynomialRegression(degree = 2)
)

# Discover candidate analytical expressions
candidates = discover(
    dataset,
    SymbolicSearch(
        operators = [+, -, *, /, sqrt],
        max_complexity = 20
    )
)

# Inspect the discovered models
results = leaderboard(candidates)

# Select one candidate
model = best_model(candidates)

# Validate it
report = validate(
    model,
    dataset;
    strategy = LeaveOneEOSOut()
)

# Inspect the expression
formula(model)
```

These are proposed APIs, not existing implementations.

The most important design principle is that a `RegressionDataset` should retain more than just \\(X\\) and \\(y\\). It must also retain scientific metadata—EOS identifiers, simulation IDs, source papers, uncertainties, physical units, and data transformations.

That will allow proper cross-validation without leaking correlated waveforms into both training and test datasets.

# Milestone 01 — Initialize EmpiricalRelationsForge.jl

## Mission

Create a new, independent Julia package called `EmpiricalRelationsForge.jl`.

The purpose of this package is to discover new empirical relations from scientific numerical datasets using classical regression, nonlinear fitting, and symbolic regression.

The initial scientific application is discovering empirical relations for gravitational-wave frequencies from binary neutron star postmerger remnants.

The architecture must remain sufficiently general to support other scientific regression problems in the future.

The existing `EmpiricalRelations.jl` package is the source of published numerical waveform measurements, EOS properties, and existing empirical models.

`EmpiricalRelationsForge.jl` must consume those data through the public API of `EmpiricalRelations.jl`. It must not duplicate its numerical database, private code, or literature extraction infrastructure.

**This milestone is for package initialization, architecture, interface design, testing infrastructure, and a minimal working regression pipeline. Do not attempt a comprehensive scientific regression study yet.**

## 5. Data preparation

Implement composable preparation routines for:

- Missing-value selection.
- Feature selection.
- Target selection.
- Unit checks.
- Standardization and scaling.
- Feature transformations.
- Duplicate detection.
- Uncertainty selection.
- Sample weighting.

All learned transformations, including feature standardization, must be fitted on training data only during cross-validation.

Retain enough metadata to reverse target transformations and express final equations in physical units.

Do not automatically add predicted empirical-relation values as ground-truth training samples.

### Physical-variable consistency

Support checks for deterministic dependencies between features.

For example, in BNS systems:

- Chirp mass depends on component masses.
- Mass ratio and chirp mass determine total mass.
- Effective tidal deformability depends on component masses and tidal deformabilities.

Flag potentially redundant feature selections.

Do not remove scientifically meaningful variables automatically.

## 7. Classical regression baseline

Implement a minimal correct set of methods.

### Ordinary least squares

Fit:

y = Xβ + ε

Use a numerically stable least-squares solver such as QR or SVD rather than explicitly computing the inverse of X'X.

### Polynomial regression

Support:

- Degree selection.
- Intercept.
- Cross terms.
- Multivariate features.
- Explicit feature names.
- Optional coefficient scaling.

For example, with two features x1 and x2, a quadratic basis may contain:

```
1
x1
x2
x1²
x1*x2
x2²
```

Use a deterministic ordering of basis functions.

Warn about rank deficiency and ill-conditioning.

### Weighted least squares

Support measurement weights using a clearly documented convention.

Do not confuse inverse-variance weights, inverse-standard-deviation weights, and arbitrary importance weights.

For uncertainty-based fitting, weights should correspond to the selected statistical loss and uncertainty definition.

The first milestone only requires basic diagonal observation weighting.

## 9. Validation architecture

Define validation strategies separately from regression methods.

The initial package should support:

- Random train/test split.
- K-fold cross-validation.
- Grouped cross-validation.
- Leave-one-EOS-out validation.

The EOS grouping functionality is especially important.

Two numerical simulations with nearly identical configurations or multiple resolution variants of the same simulation should not be treated as independent validation cases.

Develop a generic grouped splitting mechanism that can operate on EOS, simulation family, or source-paper identifiers.

### Essential validation rules

- Fit preprocessing only on training partitions.
- Never use validation targets during candidate fitting or coefficient optimization.
- Ensure grouped entities do not cross train/test boundaries.
- Use reproducible random seeds.
- Track which exact samples were assigned to each partition.

For symbolic regression, use a separate training/validation strategy when choosing a candidate from the Pareto frontier.

Do not select the final formula using performance on the untouched test set.

## 4. Scientific design decisions worth making now

There are three important considerations for the regression project.

### A. Symbolic regression should not replace classical regression

Classical fits are useful baselines. Before claiming that a discovered symbolic expression improves on existing relations, you need to establish whether it actually improves predictive accuracy outside the calibration dataset.

For instance, consider an illustrative model:

\\[ f\_{\rm peak} = a_0+a_1 M\_{\rm chirp} +a_2\tilde{\Lambda}^{-1/2}. \\]

A symbolic-regression algorithm could discover a considerably more complicated formula with a smaller training residual, but that does not mean it has found a more useful quasi-universal relation.

For your application, the ideal objective balances accuracy, physical interpretability, and generalization across EOSs.

### B. Treat EOS generalization as a primary evaluation criterion

I would prioritize leave-one-EOS-out cross-validation over ordinary random splitting when evaluating newly discovered quasi-universal relations.

The same EOS appears at multiple masses and mass ratios. Randomly distributing those simulations across training and validation sets can overestimate generalization to unseen EOSs.

Later, you can additionally test generalization across numerical codes, simulation families, and mass-ratio regimes.

### C. Give symbolic regression physically informed search spaces

Rather than allowing arbitrary combinations of mathematical operators, we can eventually constrain the search using physical considerations.

For example, compare searches over:

\\[ f\_{\rm peak} =F(M\_{\rm chirp},\tilde\Lambda) \\]

and

\\[ M\_{\rm chirp}f\_{\rm peak} =G(M\_{\rm chirp},\tilde\Lambda^{-1/2}), \\]

with units and scaling handled consistently. Dimensional analysis can significantly reduce the search space and improve interpretability.

The current SymbolicRegression.jl interface already supports operator constraints, custom losses, and template-based expression structures, providing a starting point for this kind of controlled discovery.&#x20;

## 5. Suggested follow-up milestones

Once the initialization is working, I would proceed in this order:

| Milestone                          | Goal                                                                                                                                           |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 02 — Regression foundations        | Polynomial bases, nonlinear fitting, weighting, uncertainty propagation, and feature transformations                                           |
| 03 — Symbolic discovery            | Configurable searches, dimensional constraints, expression templates, Pareto analysis                                                          |
| 04 — Scientific validation         | EOS-grouped cross-validation, bootstrap analysis, residual diagnostics                                                                         |
| 05 — Published relation benchmarks | Compare discovered models with callable relations from EmpiricalRelations.jl                                                                   |
| 06 — BNS frequency discovery       | New relations for \\(f\_{\rm peak}\\), \\(f\_{2-0}\\), \\(f\_{\rm spiral}\\), including class-dependent fits                                   |
| 07 — Candidate export              | Export verified candidate formulas, coefficients, and metadata in a format suitable for review and eventual inclusion in EmpiricalRelations.jl |

My strongest recommendation is to keep `EmpiricalRelationsForge.jl` a general scientific regression framework with a BNS-specific data adapter, rather than hard-coding neutron-star quantities throughout the regression engine.

That way, your BNS project drives the development, but the resulting package may also be useful for discovering empirical relations in other numerical-relativity, astrophysics, and computational-physics applications.
